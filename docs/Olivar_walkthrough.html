总览

Olivar 解决的是病毒/细菌全基因组扩增子 tiling（多重 PCR）的引物设计：用两管 pool，把整条基因组切成相邻重叠的扩增子，同时要求引物避开变异位点、非特异扩增位点、极端 GC / 低复杂度区域，并让同一管里的引物尽量少形成引物二聚体。

流程图

1 · build：把序列特征变成逐碱基“风险”

1.1 变异 → var_arr

每行 [START, STOP] 把区间的 var_arr 加上 FREQ（缺省按 1.0）；重叠累加；最后整体 √，把 1% 的变异放大到 0.1，让低频变异也被注意到。变异位置在序列里被大写，之后 check_SNP 就靠大写来拒绝 3' 端含变异的引物。

1.2 滑窗与碱基级平均

窗口 28 nt、步长 14（n_cycle=2），序列两端对称裁剪。每个碱基的分数 = 覆盖它的 2 个窗口的均值。GC 用碱基比例；复杂度是词长 1/2/3 的 Shannon 熵分别除以其最大值（2/4/6 bit）后取最小值，如 ATATAT… 仅 0.17，AAAA… 为 0。

1.3 非特异性 hits_arr

对每个窗口跑 blastn-short，数 HSP 条数（rough 模式）。没有 BLAST 库时全部为 0。

实测发现：在合成库里，随机窗口平均有 ≈9 条 HSP（最高 32），而植入的精确拷贝只有 ≈11 条——信号淹没在噪声里。改用仓库自己 specificity 用的 precise 过滤（3' 端无悬挂、3' 5nt 至多 1 错配、总错配≤4）后，背景≈0，植入位点清晰（20 份重复拷贝=20）。官方人类库同理：99.9% 的位置命中数>0。

1.4 组装 risk

2 · PDR 搜索：把引物设计区放到风险低的地方

PDR（primer design region）是固定 40 nt 的区域，后面才在里面挑具体引物。find_min_loc 枚举区间内所有 40 nt 窗口，算风险和，在最低的 30% 里随机选一个（既贪心又保留多样性）。generate_context 按 fP₁→rP₁→fP₂→rP₂… 依次放置，约束：

  • 扩增子长度在 [min_amp, max_amp]（默认 [0.9·420, 420]）；
  • fPₖ 必须在 rPₖ₋₁ 之前（相邻扩增子重叠）且在 rPₖ₋₂ 之后（隔一个不重叠，才能交替放进两管）。

Loss = (风险最高的 10% PDR 的风险平方和) / coverage²：只惩罚最糟的，且惩罚覆盖不足。重复 N=500·L/max_amp 次（示例 35584）取最小。

实测加速：原 find_min_loc 在 Python 里逐窗口求和，单次 generate_context ≈ 0.22 s，35584 次约 2.1 小时（单核）。对 risk 预先做一次滑窗求和，随机数消耗序列不变，结果逐位相同，单次降到 7.6 ms（≈28×），完整 35584 次约 5 分钟，得到的最优 PDR 集合与官方 .olvd 完全相同（146 个扩增子，Loss 36.55），且 35584 个 Loss 排序后逐一相等。

3 · 引物候选

在每个 PDR 里让引物 3' 端依次对齐每个位置，向 5' 端延长：先到 15 nt，再继续直到 ΔG ≤ −11.8 kcal/mol 或 36 nt；然后检查 GC、复杂度和 3' 端 5 nt 是否含变异。ΔG 是最近邻模型：

ΔG = ΔG_init + Σ ΔG_stack(相邻碱基对)
ΔG_stack = ΔH − T·(ΔS + 0.368·ln[Na⁺])   (T=60℃, [Na⁺]=0.18 M)

候选的“个体 badness”= 2·WAlignScore（引物与自身反向互补的局部比对，评估发夹/自二聚体）。某个 PDR 没有候选时自动放宽（关 check_SNP、GC 区间±0.05、复杂度−0.05）。示例中每个 PDR 平均约 15 个候选（6–24），与官方每个 PDR 的候选数完全一致，所以每个扩增子约 240 个 fP–rP 组合进入退火。

4 · SADDLE：用模拟退火最小化引物二聚体

评分 PrimerSetBadnessFast：把 pool 内所有引物的 3' 端 4/5/6-mer 和内部 7/8-mer 放入哈希计数。对每条引物的反向互补滑窗查表，命中越多、越靠近 3' 端、GC 越多，得分越高：

badness(p) = Σ  hash_k[kmer] · W_k · 1/(j+1) · 2^#GC        W = {4:1, 5:4, 6:20, 7:100, 8:500}

退火：状态=每个扩增子选哪对引物；一步=随机换一个扩增子的引物对并重算全 pool 的 Loss；以 2^((旧−新)/T) 接受变坏的移动。T₀=1000，线性降温 10 步 + 10 步 T=0，每步 1000 次尝试，每个 pool 共 20000 次。

pool-1 引物集（73 对）二聚体 badness
随机选择（20 次平均）≈ 70,000
SADDLE 优化后（官方）6,286（低 11 倍）

用原函数全量运行（官方 PDR、seed=10、单线程）约 15 分钟，得到的 fP、rP 与官方 CSV 100% 相同，两个 pool 的最终 loss 为 6524.20 / 7147.60，与官方学习曲线末值逐位相等。

实测瓶颈：每一步 ≈ 21 ms，其中 99% 花在 PrimerSetBadnessFast——一步只换 2 条引物，却把全部 146 条引物的哈希表和查表整体重算。

5 · 输出与验证

to_df 把选定的引物换算为 1-based 坐标并输出 CSV，同时生成 ARTIC/PrimalScheme 的 BED（0-based，_LEFT_1/_RIGHT_1）。示例：146 个扩增子，长度 231–410（均值 327），相邻扩增子平均重叠 125 nt，同管相邻扩增子最小间隔 8–10 nt（不重叠）。

子命令做什么实测
specificity每条引物的 GC、复杂度、ΔG、自比对、二聚体分数；有 BLAST 库时用 precise 模式预测非特异扩增子（同染色体、方向正确、间距<max_amp_len）5 项指标与官方 olivar-val_pool-1.csv 一致
sensitivity引物局部比对到 MSA 共识，统计完全匹配该引物（含简并展开）的序列比例H1N1 HA 200 条：保守区引物 99.5%，可变区引物 35%

简并模式 (--deg)：共识不再取多数碱基，而是按频率从高到低累积到 ≥70%，用 IUPAC 码表示；风险加入 sensi_arr 与 combi_arr，SADDLE 里每个变体按 1/n 浓度计入。实测：同一个可变窗口，普通共识灵敏度 33.5%，用 Y（2 种组合）后升到 75%。

改进建议

优先级：P0 低成本、已验证或几乎必然受益；P1 中等工作量、预期收益明确；P2 研究性/较大改动。每项都注明是已实测还是基于代码阅读的判断。

A. 引物迭代（设计 → 验证 → 修订的闭环）

目前仓库是“一次性设计”：tiling 给出一套引物，之后的 specificity/sensitivity 只出报告，没有回流到设计。实际项目（新毒株出现、测序发现掉扩增子）需要的是局部、可复现、不打乱已有实验的迭代。

建议依据
P0导出备选引物对：每个扩增子已有 ≈240 个 fP–rP 组合在 .olvd 里（optimize 列表），按“对 pool 总 loss 的边际贡献”排序，输出每个扩增子的 top-k 备选。某个扩增子掉线时，直接换备选，无需重跑。已实测：候选数 15.4×15.8；零额外计算
P0设计后自动“门禁”：把 specificity（precise 非特异扩增子）、sensitivity（对最新 MSA，每条引物≥95%）、二聚体离群值（官方 pool-1 的 dimer_score 均值 43、最大 270）合成一张报告，不达标的扩增子列入“待修订”清单。已实测：dimer_score 分布 0–270，均值 43
P1冻结 + 局部重设计：恢复 existing_primer 接口（代码里已有占位，PrimerSetBadnessFast(existing=…) 也支持），新增 --lock amplicon_ids / --redesign amplicon_ids：已验证的扩增子保持不变，只在失败区域重做 PDR、候选和退火，并把冻结的引物作为二聚体背景。保持扩增子 ID 不变，实验室的引物订购/稀释表不用重做。代码阅读（tiling_helper.py:407 注释掉的配置）
P1湿实验反馈入风险数组：读入每个扩增子的测序深度，对掉线区域加一项 dropout_arr（或直接给对应 PDR 加罚分），并按深度比例调整引物浓度——PrimerSetBadnessFast 已经支持 fP_conc/rP_conc，目前只用来分摊简并变体。代码阅读
P1变异库定期刷新：用最新基因组重新生成 var.csv/MSA，计算每条已有引物 3' 端 5 nt 的错配频率；超过阈值（如 1%）的引物才进入局部重设计。已实测：H1N1 可变区引物灵敏度 35% vs 保守区 99.5%
P1多种子 + 综合挑选：PDR 搜索和 SADDLE 都有随机性（seed）。用 3–5 个 seed 跑，再按“总 loss + 最差引物 + 非特异数”选最优，而不是只信一个 seed。已实测：重启次数不同，最优 Loss 差异大（1500 次 151 vs 35584 次 36.6）
P2备份/替代引物池（ARTIC v4/v5 风格）：对已知易掉线或高变异区域，设计一对“替代引物”放入同一 pool 或第三管，浓度较低。需要把 N_POOLS=2（注释“not to be changed”）参数化。代码阅读

B. 算法

建议依据
P0PDR 窗口求和改前缀和（find_min_loc）。结果逐位相同，单核 28×。另（代码阅读）：pool.imap 的每个任务元组都携带 3 万长的 risk 数组，可用 initializer 放全局以减少进程间传输。已实测：215 ms → 7.6 ms；35584 次 2.1 h → ~5 min
P0非特异性计数改用 3'-端感知规则：build 阶段也用 precise（或等价的“3' 端精确匹配长度”）来数命中，并对重尾取 log1p 而非除以最大值。已实测：rough 信噪比≈1，precise 干净；人类库 99.9% 位置命中>0、/max 后 99 分位仅 0.048
P0修复 bug #3–#5（简并命中下标、MSA 重复加载、死代码 check_BLAST）。见“发现的问题”
P1SADDLE 增量更新：维护 k-mer 计数和“每条引物的反向互补 k-mer 命中表”，一步换 2 条引物时只更新受影响的项，复杂度由 O(全部引物) 降到 O(改动)。同时可以用已计算的 comp_badness 做定向变异（以与单引物 badness 成比例的概率选扩增子）。已实测：99% 时间在全量重算；20000 步×2 pool 约 15 分钟，规模再大（上千重）二次增长
P1变异风险按 3' 端加权：目前 PDR 风险是 40 nt 内逐碱基求和，而引物 3' 端的错配远比 5' 端致命；check_SNP 也只看 3' 5 nt 的有/无。建议风险按距 3' 端的距离衰减（如 exp(−d/8)），并按错配类型（3' 端 G:T 等）区分。代码阅读；机制上合理，需用 §10.2 类实验量化
P1PDR 与引物候选联合评分：现在先用 40 nt 平均风险选 PDR，再在 PDR 里选引物，两步解耦。更好的是用候选引物自身的 3' 加权风险给每个 PDR 打分（或直接让 PDR 的分数 = 该 PDR 最好候选的分数），避免“PDR 平均风险低、但所有候选 3' 端都踩在变异上”。代码阅读
P1热力学模型升级：目前 ΔG 用固定 ΔH/ΔS 表 + 仅 Na⁺ 校正，没有 Mg²⁺、dNTP、引物浓度；没有 Tm 概念，用 ΔG(60℃) 阈值间接控制。可接入 primer3-py 的 Tm、发夹、同/异源二聚体 ΔG（只对 SADDLE 之后的最终候选和最差 N 条引物做精算，不进退火内循环）。代码阅读；官方引物长度 16–34 nt，说明 ΔG 阈值驱动的长度变化很大
P1扩增子层面的指标：目前扩增子长度只受 [min,max] 约束，没有 GC、二级结构、预测扩增效率。覆盖均匀度主要由这些决定；可在 PDR 评分里加入 amplicon GC / 长度均衡项，在 pool 分配时考虑长度/GC 平衡。代码阅读（示例长度 231–410）
P2PDR 布局用动态规划/束搜索代替随机重启：问题是链式结构（相邻扩增子耦合、隔一个耦合），状态为 (fPₖ 起点, rPₖ 起点)，每维只有 ≤~170 个选择，可以在目标 Σ风险 或 minimax 下精确求最优，并给出可证明的最优覆盖。当前随机重启的最优 Loss：1500 次为 151，35584 次才到 36.6。已实测：1500 次最优 151 vs 35584 次 36.6；DP 属推断，需实现验证
P2池数参数化（N_POOLS）与退火调度自适应（温度/步数随 pool 规模和接受率调整，而非固定 1000×20）。代码阅读

C. 数据库选择

Olivar 有三类“数据库”：① BLAST 背景库（决定非特异性）、② 变异库（决定哪些位置要避开）、③ 参考/MSA（决定设计靶标）。示例只给了一个 GRCh38 背景库（772 MB，Git-LFS，克隆时若没装 LFS 会得到指针文件，BLAST 报 IndexError）。

建议理由 / 依据
P0按样本类型组合背景库，而不是只用人类基因组：
• 临床鼻咽拭子：人类基因组 + 转录组/rRNA（RNA 病毒经反转录，cDNA 背景主要是转录本）+ 近缘病毒（SARS-CoV-1、MERS、229E、NL63、OC43、HKU1）+ 常见呼吸道病原与定植菌（流感、RSV、鼻病毒、链球菌、葡萄球菌、嗜血杆菌）；
• 废水/环境：再加 NCBI RefSeq 代表性细菌/病毒基因组或 core_nt 的子集；
• 实验对照：PhiX、质控序列。		脱靶来自“样本里真实存在的核酸”。库越贴近样本，预测越有价值；库越大，rough 模式的噪声越高（需配合 precise）。
P0库路径与 LFS 的防呆：运行前检查 .nsq 是否是 LFS 指针（首行 version https://git-lfs…），给出明确错误；README 里直接给“最小可用库”的构建命令（makeblastdb -parse_seqids -hash_index -taxid）。已实测：本仓库 .nsq 为 134 字节指针文件
P1用 k-mer 索引代替“每窗口一次 BLAST”：对背景库预建 3' 端 12–16-mer 计数（KMC/Jellyfish）或用 bowtie2/BWA 短序列模式，做 3' 端精确匹配 + 允许 1–2 错配的计数。比 blastn-short 快一到两个数量级，且天然 3'-端感知；precise 在 2134 个窗口、30 万碱基的小库上就要 135 s，3 Gb 人类库上会很慢。已实测：rough 2 s vs precise 135 s（小库）；precise 才有信噪比
P1把引物级特异性接入设计：候选引物每个 PDR 仅约 15 条（全基因组约 4,600 条），对它们逐条做 3' 端感知的脱靶计数（缓存后几分钟），作为 badness 的一项（代码里本来就有 1000·log10(count)⁴ 的占位）。已实测：候选总数；check_BLAST 现为死代码
P1变异库用持续更新的公共来源：Nextstrain / GISAID / NCBI Virus / CoV-Spectrum 的位点频率（最好带时间窗，近期权重大），替代一份静态的 Delta/Omicron CSV。同时区分 SNP 与缺失、保留 3' 端附近的变异详情。MSA 模式下 --min-var 默认 1% 也应随样本量调整。代码阅读；示例 CSV 为 397 个位点（Delta/Omicron 特征）
P1多亚型/高变靶标用 MSA + 简并模式，并把共识阈值（现硬编码 70%，代码注释“Can set this as a threshold later”）做成参数。已实测：可变窗口灵敏度 33.5% → 75%（1 个简并碱基）
P1中间文件格式：.olvr/.olvd 改为 JSON + NPZ/Parquet 并写入版本号与配置哈希（含 BLAST 库的路径与修改时间），保证可复现与可迁移，避免 pickle 的安全和版本问题。已实测：.olvd 15.7 MB；.olvr 与当前输出的 comp_arr 差 2×

建议的落地顺序

  1. 先做 P0：修 bug #3–#5、PDR 前缀和、非特异性改 3'-端感知、BLAST 临时文件改到临时目录、库路径防呆。几乎无风险，收益立即可见。
  2. 再做 P1 里与“迭代”直接相关的三项：备选引物导出、冻结+局部重设计、变异刷新触发的局部重设计。
  3. 然后做 SADDLE 增量更新和 3' 加权变异风险；用 notebook §11 里的对照框架（官方结果作为回归基线）验证不退化。
  4. 最后评估 P2（DP 布局、热力学升级、多池）。
