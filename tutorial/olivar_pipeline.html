Olivar 多重 PCR tiling 设计流程解析

基于仓库 olivar 1.3.3 源码逐文件阅读，并在配套 notebook 中逐步复现。包含总流程图、每一步的公式与代码位置、已证实的代码问题，以及针对引物迭代、算法和数据库选择的改进建议。

ATCG

Overview总流程

Olivar 的核心思想是先选区域，后选引物。传统工具（PrimalScheme 等）直接在序列上枚举引物对；Olivar 先给每个碱基算一个“风险值”，在风险低的位置划出 40 nt 的引物设计区（PDR），再在 PDR 内部生成引物，最后用 SADDLE 在候选里挑组合以降低二聚体。

Step 1输入与参考序列

模式 2：一条参考序列加一张变异表（START, STOP, FREQ，1 起始、闭区间）。模式 1：一组序列，先由 MAFFT 比对，MSA.variant_call() 以共识序列为参考，统计每列与共识不同的比例，频率 ≥ min_var（默认 1%）的位点写入变异表。之后两种模式走同一条路径。

变异在序列里被写成大写，其余为小写，这是后面 check_var 判断引物 3' 端是否踩到变异的依据。

共识序列只用“每列最多的碱基”，所以它不一定是任何一条真实序列。插入只被记在插入点前一个位置。

Step 2三个基础打分

basic.py · design.py
复杂度 C = min( H₁/2, H₂/4, H₃/6 ), H_k = −Σ p_w · log₂ p_w (k = 1,2,3 nt 词) ΔS' = ΔS + 0.368 · ln[Na⁺] ΔG_ij(T) = ΔH_ij − T·ΔS'_ij / 1000 ΔG(引物) = 0.2 + 5.7·T/1000 + Σ ΔG_(s_i, s_i+1) T = 60 °C, [Na⁺] = 0.18 M

引物从 3' 端向 5' 端延长，直到 ΔG ≤ −11.8 kcal/mol 或达到 36 nt。这样每条引物的结合强度大致一致，长度随序列变化。这里没有 Mg²⁺、dNTP、引物浓度校正，也不输出 Tm。

Step 3build：把参考序列变成风险分量

build_helper.run_build
  1. 以 word_size = 28、offset = 14 切 word，相邻 word 重叠一半。
  2. 对每个 word 算 GC 与复杂度；blastn-short（rough 模式：evalue 10，reward 1，penalty −3）计该 word 在 BLAST 库里的命中条数。
  3. 每个位点被 2 个 word 覆盖，取两者平均，得 gc_arr / comp_arr / hits_arr；两端各丢掉 14 nt。
  4. 变异：同一位点的频率相加，再取平方根，用来放大低频变异。
  5. pickle 写成 .olvr。

notebook 第 3.3 节不调用 run_build，自己切 word 重算，GC、复杂度、变异三个数组与官方结果和仓库自带的 .olvr 逐元素一致。

Step 4风险数组

低复杂度复杂度 < 0.4 记 10.5 · w_lc

变异项的权重是 10，其余项最多 1，所以只要某位点有 1% 以上的变异，PDR 就会尽量绕开。GC 和复杂度是 0/1 的硬阈值，没有渐变。

实测在 28 nt word 上，rough 模式（evalue 10）会产生大量偶然短命中：在一个 0.4 Mb 的演示库里，植入了 80 nt 同源片段的区域与随机区域的平均命中数几乎一样（约 15 对 14）。命中数只能当相对尺度用，这也是 tiling 里要除以最大值的原因，同时说明它对“真同源”不敏感（见数据库建议）。
仓库自带的 .olvr 缺少 sensi_arr、combi_arr，直接喂给 1.3.3 会 KeyError。notebook 里补零数组后，手算 risk 与 example_output/EPI_ISL_402124_risk.csv 一致。

Step 5PDR 优化

tiling_helper.generate_context · find_min_loc
  • PDR 固定 40 nt。find_min_loc 枚举区间内所有窗口，从风险最低的 30% 里随机选一个。
  • 每个扩增子的 fP-PDR 必须落在上一个扩增子 rP-PDR 之前，且在上上个 rP-PDR 之后；这样相邻扩增子重叠，奇偶号分到两个 pool，同 pool 内不重叠。
  • 一套 PDR 的损失：风险最高的 10% 的 PDR 取平方和，再除以覆盖率的平方。
  • 重复 N = 500 · iterMul · L / max_amp_len 次（SARS-CoV-2 为 35,584 次），保留损失最小的一套。
Loss = Σ_{r ∈ 风险最高 10%} r² / coverage²

这是随机重启的贪心构造，不是对某个解的局部搜索。每次重启彼此独立，搜索空间很大时靠多次抽样逼近。

实测单次 generate_context 约 0.16 s，大头是 find_min_loc 对每个窗口都用 Python sum() 重新求和。预先算一次所有窗口和（滑动窗口内顺序累加，浮点结果与 sum() 逐位相同），在 50 个种子上与原实现给出完全相同的 PDR，单次约 6 ms，约快 25 倍。

Step 6PDR 内生成引物候选

design.primer_generator.get
  1. 3' 端位置从 PDR 最右端向左扫描；rP 先取反向互补，使两种引物都是“3' 端朝外”。
  2. check_var：3' 端最后 5 nt 含大写（变异）碱基的丢弃。
  3. 先延长到最短 15 nt，再延长到 ΔG ≤ dG_max，上限 36 nt。
  4. 过滤 GC 0.2–0.75、复杂度 ≥ 0.4。
  5. 单引物“坏度”＝2 × WAlignScore：引物与自身反向互补做局部比对（GC 配对 +2，AT +1，错配 −2，gap −3），按离 3' 端距离扣分，取 1.5^(分数−6)。

某个 PDR 没有任何候选时，get_primer 按失败最多的原因放宽：关闭变异检查、GC 范围各放宽 0.05、复杂度降 0.05。

Step 7SADDLE：用模拟退火最小化二聚体

design.PrimerSetBadnessFast · tiling_helper.optimize

评分：把池内所有引物 3' 端的 4/5/6-mer 放进一个哈希表，所有 7/8-mer 放进另一个。对每条引物取反向互补后滑动查表，查到就说明池里有能与它互补的片段。命中得分 = 权重 × 次数 × 1/(位置+1) × 2^GC数，权重为 4-mer 1、5-mer 4、6-mer 20、7-mer 100、8-mer 500。

搜索：状态是“每个扩增子选哪一对 (fP, rP)”。每步随机换掉一个扩增子的引物对，按 Loss 变化以 2^(ΔL/T) 的概率接受变差。温度从 1000 + 10·max(n/2−100, 0) 线性降到 0，再用同样步数的零温贪心收尾，每个温度 1000 次尝试。简并模式下，一个扩增子的多个展开变体按 1/变体数 的浓度计入。

每次尝试都 deepcopy 三个字典，并从头重算整个池的评分，复杂度随池大小增长；而一次突变只改一个扩增子。

Step 8验证：特异性与灵敏度

  • specificity：对每条引物做 blastn-short precise 模式（evalue 5000，reward 1 / penalty −1）。一条命中算“可延伸”需满足：3' 端无悬垂、3' 端 5 nt 最多 1 个错配、总错配 ≤ 4。再在同一条序列上找方向相对、间距小于 max_amp_len 的引物对，作为预测的非特异扩增子。
  • sensitivity：把引物局部比对到 MSA 共识上，取出对应列，统计与引物（含简并展开）完全一致的序列比例。

两者都是定性筛查：没有热力学扩增模拟，没有 3' 错配的位置加权，灵敏度是“全匹配”二值，不区分一个远端错配和一个 3' 端错配。

Audit代码审计：已确认的问题

下面每一项都对应代码里的具体行，前三项在 notebook 第 9 节有运行验证。

已修Python < 3.12 无法 import。main.py 的 f'{config['title']}.log' 在嵌套同种引号，3.8–3.11 报 SyntaxError，而 setup.py 声称支持 ≥ 3.8。本分支已改为双引号外壳。
已证实简并模式下 BLAST 命中数写错下标。build 给展开序列命名 query_{word}_{variant}，rough 模式解析时用 split('_')[1]（word 编号）当下标，而 build 汇总时用的是展开列表下标，二者不一致。多变体时命中数被记到别的 word 上并互相覆盖。
已证实复杂度计算区分大小写。build 把变异位点改成大写，basic.get_complexity 用 Counter 直接数字符，A 与 a 被当成两种碱基。EPI_ISL_402124 中 2134 个 word 里有 254 个因此复杂度被抬高（最大 +0.117），低复杂度区域里的变异位点反而躲过惩罚。get_GC 处理了大小写，两个函数不一致。修法：在函数入口统一 seq.lower()。
已证实旧 .olvr 不兼容。缺 sensi_arr/combi_arr 直接 KeyError，应在载入时补零并给出提示。

读代码发现的其它风险

  • 临时文件在包目录里，且固定文件名。BLAST_query.fasta、BLAST_result.tsv 写入 CURRENT_DIR：只读安装会失败，同时跑两个任务会互相覆盖。应改用 tempfile。
  • 引物候选可能死循环。get_primer 的 while len(fP)==0 只处理三种失败原因；若失败最多的是 end_fail，或 SNP_fail 但检查已关闭，设置不变，下一轮结果相同，会一直循环。
  • 简并 build 每个 word 重载整个 MSA。get_sensitivity 里每次调用都 MSA(msa_path) 并重算共识；4,227 条 H1N1 序列时这一步会成为主要耗时。应在进程初始化时加载一次。
  • 共识每次重算为非简并版本。MSA.__init__ 固定用普通共识，而 get_sensitivity 随后才改成简并共识，每个 word 重复两遍。
  • pickle 作为交换格式。.olvr/.olvd 载入即执行任意代码，README 已警告，但更稳妥的是 npz + json。
  • 已有引物无法并入。optimize 里 existing_primer = [] 被写死，注释掉的配置项说明这个功能曾存在，现在无法复用旧 panel。
  • pool 数写死为 2（N_POOLS），扩增子按奇偶交替；扩增子很多时二聚体评分会随池增大而恶化，缺少 3 pool 以上的选项。
  • get_complexity 对短序列会除零。长度 < 3 时 len(seq)-2 为 0 或负。

Improve · 1引物迭代

当前流程是一次性设计：设计 → 出 csv → 结束。实际多重 PCR 几乎都要多轮迭代，Olivar 缺少让数据回流到设计里的通道。

  B --> C["每个扩增子的覆盖深度
掉落 dropout"]
  C --> D["更新风险数组
掉落位点加罚分"]
  D --> E["固定表现好的引物
仅替换掉落扩增子"]
  E --> F["设计 v2（existing_primer）"]
  F --> B

1. 实验数据回流

读入每个扩增子的覆盖深度，把低于均值 10–20% 的扩增子标成掉落，在其引物所在位置给风险数组加一个经验罚分，同时保留表现好的引物。风险数组本来就是可加的，这一步改动很小。

2. 恢复“已有引物”

把 existing_primer 恢复成参数：固定的引物仍参与二聚体评分，只在掉落扩增子的候选里搜索。这也让现有 panel 在病毒出现新变异时只做局部更新。

3. 浓度作为变量

简并模式已经有“每个变体按 1/n 浓度”的机制。把它推广：掉落扩增子的引物浓度上调，过度扩增的下调，并把浓度写进输出表，作为迭代的第二个旋钮（实验中调浓度比重设计便宜得多）。

4. 变异库的时间维度

病毒变异频率随时间变化。把变异表带上时间窗（如最近 6 个月的 GISAID/Pathoplexus 频率），每次迭代自动刷新风险数组，并报告“哪些引物的 3' 端落在频率上升的位点”。

5. 多候选而非单解

当前只输出一个最优方案。同时输出每个扩增子的前 3 个备选引物对（已经在候选里），迭代时无需重跑整个流程就能就地替换。

6. 引物浓度与 Tm 一致性

对设计出的引物用含 Mg²⁺ 的模型（如 Biopython Tm_NN）重新评估 Tm。notebook 第 9.2 节给出了本次设计的 Tm 分布；ΔG 阈值只控制强度，池内 Tm 的离散度没有被约束。

Improve · 3数据库选择

Olivar 用两类数据库，两者目前的选择都比较粗：BLAST 背景库（要避开的序列）和变异来源（要避开的位点）。

背景库（非特异性）

样本类型建议的背景库理由
人临床样本（RNA 病毒）GRCh38 + 人类转录组（RefSeq mRNA）+ rRNA（SILVA / RefSeq rRNA）样本经逆转录，cDNA 里是转录本，剪接后的外显子连接序列不在基因组库里；rRNA 占总 RNA 的大头
人 DNA 病毒T2T-CHM13 或 GRCh38 的完整版（含 alt、decoy）README 里的示例只含 23 条染色体和 MT，漏掉未定位序列与 alt 片段
宏基因组 / 环境样本常见共生菌与近缘病原的代表基因组非特异来源不是人，用人基因组不会给出任何风险信号

共循环近缘病原NCBI RefSeq 病毒代表基因组、近缘亚型 / 近缘种鉴别诊断 panel 里的主要风险是近缘靶标之间的交叉

怎样用好背景库

  • 换掉“命中条数”这个指标。实测 28 nt word 的偶然命中会淹没真同源（见第 4 步），建议只统计 3' 端 10–12 nt 精确匹配且全长至少 ≥ 85% 一致的命中。
  • 用 k-mer 索引代替 blastn-short 扫整库。对 28 nt 的 word，每次跑 blastn-short 扫 3 Gb 基因组很慢（仓库 BLAST 库的 .nsq 就有 772 MB）。建立一次 12–16-mer 的哈希或 FM 索引，按“被命中的 k-mer 数”算风险，复杂度与库大小基本无关。BLAST 保留给最终的 specificity 复核。
  • 命中应按 3' 端加权。现在命中数把全部 28 nt word 里任意位置的命中等同计数；真正导致非特异扩增的是 3' 端匹配。可以把 word 拆成“后 10 nt”和“前 18 nt”，只对 3' 端精确匹配加重权。
  • 归一化方式。hits / max(hits) 让一个极端值把其余位点的风险压平。可改成 log(1+hits) 或分位数。
  • 拆分库而不是合并。人、rRNA、近缘病原各建库、各给权重，输出里分别列出，用户才知道风险来自哪里。
  • 仓库本身的建议。示例的 GRCh38 库放在 Git LFS 里，clone 不带 LFS 就会 IndexError；改为首次使用时从 NCBI 下载并校验，或在报错里直接提示 LFS。

变异库

  • MSA 输入的变异频率取决于抽样：4,227 条 H1N1 序列的频率不等于当前流行频率。建议对序列按采样日期加权，或使用 Nextstrain / Pathoplexus / GISAID 的最近窗口。
  • 变异表只有频率，没有谱系。对于一个子谱系独有的变异，更合适的目标是“覆盖所有主要谱系”，而不是“避开所有 ≥ 1% 的位点”。
  • 对高变异靶标（流感、HIV），--deg 的 70% 累计阈值是写死在 _get_consensus 里的，应暴露为参数。
